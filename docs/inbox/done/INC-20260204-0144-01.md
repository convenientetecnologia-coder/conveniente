### INC-20260204-0144-01 - P1 - CT Removidos: remover coluna “Motivo” e centralizar histórico no cadastro

- **State**: `done`
- **Rollout**: `deployed`
- **Validation**: `passed`

#### Relato (humano)
- Ao remover uma participação em **Ativos**, o sistema pede “Motivo/nota (opcional)”.
- A equipe precisa ter **histórico confiável** de remoções/reprovações (com data/hora e motivo) para decidir reentrada.

#### Decisão de produto (durante o INC)
- **Remover** a coluna **Motivo** da aba **Removidos** (não é o melhor lugar para histórico).
- Criar um bloco **Histórico (Removidos/Reprovados)** no **modal de cadastro (driver-level)**:
  - mostra **todas** as remoções/reprovações do cadastro (multi-cidade),
  - ordenado por tempo (eventos),
  - com scroll interno quando ficar grande.

#### Causa raiz (evidência)
- O “Motivo” precisava ser persistido/centralizado como **evento** do cadastro (driver-level), não como coluna na tabela “Removidos”.
- Evidência (runtime):
  - `c:\sitechatbot\.cursor\debug.log` com runId `ct_driver_motives_central_v1` provando:
    - `membership_removed`/`membership_rejected` sendo anexados com `payload.note` no backend
    - `openCadastroModal` carregando `/api/events?driverId=...` e renderizando o histórico
  - Foi necessário hard refresh (cache) em uma rodada; `ct_build_id_v1` foi usado como prova de rollout durante debug.

#### Implementação (arquivos)
- Backend (persistência do histórico via eventos):
  - `C:\sitechatbot\convenientetecnologia\lib\ctMembershipStore.js`
    - Em `setMembershipStatus`, ao virar `removed`/`rejected`, chama `ctStore.appendEvent({ type: "membership_removed"/"membership_rejected", payload: { membership_id, city_uf, city, note } })`.
- Backend (API):
  - `C:\sitechatbot\convenientetecnologia\index.js`
    - `/api/events` já existia e passou a ser o endpoint usado pelo cadastro para buscar o histórico (filtro por `driverId`).
- Frontend (UI):
  - `C:\sitechatbot\convenientetecnologia\public\ct.js`
    - Remove coluna “Motivo” da aba **Removidos**.
    - Adiciona bloco **Histórico (Removidos/Reprovados)** no `openCadastroModal` (driver-level), com scroll interno.

#### Critério de aceite (final)
- Ao remover/reprovar com nota:
  - A aba **Removidos** não exibe coluna “Motivo”.
  - O **cadastro (driver-level)** exibe o bloco **Histórico (Removidos/Reprovados)** com:
    - data/hora,
    - tipo (removido/reprovado),
    - ator (quando houver),
    - cidade/UF (quando houver),
    - motivo/nota (ou “— sem motivo —”).

#### Operação
- **Reinícios**: CT (sitechatbot) — humano reinicia com `node index.js` para aplicar backend/frontend.
- **Rollback**: reverter alterações em `ct.js`, `index.js`, `ctMembershipStore.js` (CT) e reiniciar `node index.js`.
