# INC-20260409-2000-01 — Stock provision auth mode (cookies vs login/senha)

Status: `in_progress`  
Prioridade: `P0`  
Projeto: `conveniente`

## Contexto

Operação pediu alternância segura do cadastro de contas no `stock_provision`:
- manter fluxo legado por cookies;
- habilitar fluxo novo por login/senha;
- alternar por flag de ambiente, com rollback rápido sem patch.

## Objetivo

Implementar modo de autenticação por flag no runtime:
- `STOCK_PROVISION_AUTH_MODE=cookies_first|password_first`
- padrão inicial: `password_first` (com rollback imediato para `cookies_first`).

## Critérios de sucesso

1. Em `cookies_first`, pipeline atual permanece sem regressão.
2. Em `password_first`, `stock_provision` usa `login_remediate`.
3. Se falhar login (captcha/checkpoint/identity/credencial/UI bloqueada):
   - perfil entra em modo humano;
   - lote continua para as próximas contas.
4. Rollback operacional: trocar flag para `cookies_first` + restart.

## Evidências esperadas

- Código:
  - `C:\conveniente\scripts\dashboard.js`
  - `C:\conveniente\scripts\worker.js`
- Logs:
  - `C:\conveniente\dados\provision_audit.jsonl`
  - `C:\conveniente\dados\login_remediate_evidence.jsonl`
- CT ACK:
  - `C:\sitechatbot\dados\logs\<hostId>\ack_<cmdId>.json`

## Risco / rollback

- Risco principal: regressão no cadastro legado.
- Mitigação: branch por flag com default em `cookies_first`.
- Rollback: `STOCK_PROVISION_AUTH_MODE=cookies_first`; restart manual `node index.js`.
