# INC-20260410-1930-01 — Capacidade 8GB/worker (15 contas/worker; 30 contas em 16GB com 2 workers)

Status: `in_progress`  
Prioridade: `P0`  
Projeto: `conveniente`

## Contexto

Frente aberta para validar mudança de topologia de workers:

- regra alvo de capacidade: `1 worker / 8GB`;
- densidade mantida: `15 contas / 8GB` (equivalente a `30 contas / 16GB`);
- em host de 16GB: operar com 2 workers em vez de 1 worker único.

## Objetivo

Reduzir blast radius e aumentar estabilidade sob carga, mantendo capacidade total planejada por host, com rollout controlado e rollback simples.

## Evidência técnica inicial (pontos de código auditados)

- `C:\conveniente\scripts\ramPolicy.js`
  - `calcNodesByTotalMemMB()` usa heurística atual de `16GB por node`.
- `C:\conveniente\scripts\memoryPlan.js`
  - `NODE_SEG_MB=16384` e `MAX_PER_NODE=30`.
- `C:\conveniente\scripts\worker.js`
  - uso de shard via `SHARD_PROFILES`, `SHARD_SET`, handler `set-shard`.
- `C:\conveniente\scripts\dashboard.js`
  - agregação de status por node e allowlist estática (`status_node_1..status_node_6`).

## Hipóteses a validar

- H1: mais workers por host reduz instabilidade local por isolamento de falha.
- H2: custo de overhead adicional de worker é compensado pela queda de churn/recovery.
- H3: manter 30 contas em 16GB com 2 workers é viável com melhor previsibilidade operacional.

## Escopo de auditoria pré-código

1. Política de cálculo de nodes/memória (`ramPolicy`, `memoryPlan`).
2. Compatibilidade com shard runtime (`worker`).
3. Limites operacionais de status/logs por node (`dashboard`).
4. Matriz de teste controlado por host e critérios `Go/Caution/Stop`.

## Entregáveis

1. Checkup técnico ponta a ponta para capacidade 8GB/worker.
2. Lista fechada de mudanças mínimas por arquivo (pré-implementação).
3. Plano canário com rollback.

## Critério de sucesso

- confirmar, com evidência, melhora de estabilidade sem reduzir capacidade útil por host;
- garantir rollout seguro sem perda de provisão/consistência operacional.

## Atualização 2026-04-10 (patch mínimo aplicado no runtime)

  - `calcNodesByTotalMemMB()` atualizado para `1 node / 8GB` (`ceil`).

  - `MAX_PER_NODE` alterado de `30` para `15`.
