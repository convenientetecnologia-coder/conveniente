## Sintoma (humano)

- Clicou “Abrir Todos”, aparentemente “não aconteceu nada”.
- Ao clicar de novo, o painel mostrou:
  - `open_all_lock_busy owner=open_all_map:<timestamp>`

## Diagnóstico (GPT)

- O endpoint `/api/perfis/open-all-24h` sempre gerava um **novo** `lockOwner` (`open_all_map:<agora>`).
- Se o 1º clique adquiriu o lock e o usuário clicou de novo durante o TTL, o 2º clique naturalmente batia em `busy` e o painel tratava como falha.
- Isso é um problema de **idempotência/UX**: o sistema pode estar rodando corretamente, mas o operador não tem confirmação e clica de novo.

## Correção aplicada (código)

- **Servidor** (`scripts/api_perfis.js`):
  - Se já existir lock `open_all_map` e `desired._openAll.active=true` com o mesmo owner:
    - retorna `ok:true, alreadyRunning:true` (sem erro).
  - Se existir lock `open_all_map` mas `desired._openAll` não estiver ativo (stale):
    - libera o lock e tenta adquirir 1x novamente.
- **Painel** (`public/index.html`):
  - Se receber `alreadyRunning:true`, mostra feedback e atualiza o painel (evita “2º clique = erro”).
