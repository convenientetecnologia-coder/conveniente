## Fix aplicado (canônico)

### 1) Comandos de restore (enterprise) no executor do host

- Implementado no `conveniente` um mecanismo “DR” via comandos CT:
  - `backup_restore_probe`: valida path do backup e reporta contagens/hash.
  - `backup_restore_merge`: `dry_run` (relatório) e `apply` (escrita atômica).
- Segurança:
  - allowlist de path: somente sob `C:\conveniente\_backup_auto\...` ou `C:\conveniente\_backup_auto_root\...`
  - `apply` adquire `provision_lock` (evita concorrência com provisão)
  - rollback automático: salva “antes” em `C:\conveniente\dados\_ops_audit\restore_<ts>_*.before.json`
- Código:
  - `C:\conveniente\scripts\dashboard.js` (novos handlers + dispatcher)

### 2) Policy de merge (alinhada com o humano)

- `perfis.json`: união por `nome` sem duplicar, preservando ordem do backup e adicionando os 7 novos no final.
- `desired.json`: manter `desired` do backup para perfis antigos + manter `desired` atual para os 7 perfis novos.
