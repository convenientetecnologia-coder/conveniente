# INC-20260219-0910-01 — Webhook dual + distribuição anônima com link tokenizado

- **Sistema**: `sitechatbot` + `notificador`
- **State**: `done`
- **Rollout**: `pilot_ready`
- **Validation**: `pass`

---

## Sintoma/necessidade (humano)

- hoje o grupo recebe pedido com contato direto do cliente;
- novo fluxo exige ocultar telefone/link do cliente no grupo;
- grupo deve receber só dados do pedido + link com código rastreável;
- motorista clica e cai no número de operação para entrar na fila.

Contexto operacional (canônico):
- o link tokenizado é o gatilho do novo fluxo que culmina em cobrança (seg-sex 08:00) e possível bloqueio (15:00);
- funcionamento interno: seg-sex 10:00–17:00 (impacta comunicação/SLA das mensagens ao motorista).

---

## Decisões pendentes

- formato do código (`leadToken`) e TTL;
- estratégia anti-fraude/reuso do link;
- mapeamento canônico entre pedido original e `leadToken`;
- regra de idempotência para mensagens repetidas no webhook.

---

## Evidência obrigatória antes de codar

- endpoints atuais que publicam pedido em grupos (`path` e função);
- evidência de webhook dos 2 números (payload real sanitizado);
- `requestId/cmdId` de testes de entrega de mensagem;
- prova de persistência de correlação `pedido -> token`.

---

## Critério de sucesso

- em grupo piloto, nenhum pedido novo expõe contato do cliente;
- link abre fluxo correto no número de operação;
- token identifica unicamente o pedido sem colisão.
