## Mapa de impacto (obrigatório)

### Fluxo ponta a ponta (alto nível)

1. **Detecção da primeira tela**:
   - `detectLoginRequired` detecta a primeira tela "Confirme que você é humano"
   - Retorna `reason: 'captcha_persona_pre_screen'` ou similar
   - `identityFlow` ou `reconcileHumanState` captura isso
   - Chama função para auto-clicar "Continuar"

2. **Detecção da segunda tela (captcha)**:
   - `detectLoginRequired` detecta a tela do captcha (com imagem)
   - Retorna `reason: 'captcha_persona'`
   - `identityFlow` captura isso
   - Faz 3 tentativas (revalidar/click-se-habilitado/reload) **sem resolver captcha**
   - Se ainda bloqueado após 3 tentativas, invoca humano via `failFastToHuman`

### Callers (quem chama esse fluxo)

- `reconcileHumanState`: verifica periodicamente o estado do navegador
- `identityFlow`: fluxo de identidade/captcha
- `login_remediate`: após falha de cookies/login

### Callees (o que esse fluxo aciona)

- Groq API (nova integração)
- `failFastToHuman`: se todas as tentativas falharem
- `ensureHumanOverlay`: se invocar humano

### Estados tocados

- `perfis.json`: flags `loginRequired`, `loginRemediateFailed`
- `status.json`: estado do navegador
- `provision_audit.jsonl`: logs de tentativas de OCR

### Efeitos colaterais possíveis

- Se a primeira tela não for detectada corretamente, pode deixar Virtus online indevidamente
- Se o OCR falhar mas o sistema não detectar, pode ficar preso
- Se a imagem mudar durante as tentativas, pode precisar de mais tentativas

### Risco de regressão

- Mudança na detecção de captcha pode causar falsos positivos/negativos
- Integração com Groq API pode falhar (rate limit, API key inválida, etc.)
- **Mitigação**: detecção ultra robusta (múltiplos sinais), retry com backoff, fallback para humano se API falhar
