CONTRATO — Porteiro e o vigia do WINDOWS, nao filho do index
============================================================
Data: 2026-08-31

O Porteiro (C:\auto_vigia, tarefa ConvenientePorteiro ao logon) e um
sistema a parte. Ele TEM que funcionar com o Conveniente DESLIGADO:
  - reboot 04:00-04:20 + TEMP + Lixeira
  - AUTO_BOOT: se o index nao estiver no ar, o Porteiro sobe o CMD
  - NetGuard / ConvenienteNetBoot no startup

O index.js NAO e o dono. O index so CORRIGE a versao quando voce liga
o Conveniente:
  - se o arquivo/loop for o velho (mem_soft / v5.1.13) → instala v5.2.0-nomem
    e a TAREFA DO WINDOWS sobe o loop (schtasks /Run). Nao fica filho do Node.
  - se ja for o correto e estiver vivo → o index NAO mexe.

RAM/StandbyList: o Conveniente cronometra (chromeMemorySweep no index) e
pede ao Windows a tarefa SYSTEM ConvenienteDiskClean. O loop do Porteiro
NAO dispara o exe (MemClean=OFF).

1. SERVIDOR NOVO
   irm ... | iex
   fecha, reabre:
     cd \
     if (Test-Path "C:\conveniente") { Remove-Item -Path "C:\conveniente" -Recurse -Force }
     git clone https://github.com/convenientetecnologia-coder/conveniente.git "C:\conveniente"
     cd C:\conveniente
     npm install
   Clique o S (INICIAR_SISTEMA.vbs). Sem admin. Sem OK.
   Sobe o Conveniente e arma o vigia (C:\auto_vigia + tarefa ao logon + loop).
   Lixeira, reboot 04h, religar o CMD: o vigia faz.

2. MAE JA EXISTENTE / VERSAO NOVA DO VIGIA
   git pull, clique o S. Se o arquivo do vigia mudou: copia, mata o loop
   velho, sobe o novo. O Conveniente nao cai. Sem admin.
3. PROVA
   STATUS: Ver=v5.2.0-nomem  MemClean=OFF

   Tarefa ConvenientePorteiro = Running (nao depende do Node estar aberto)
